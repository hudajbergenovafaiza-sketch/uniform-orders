# Ошибки ИИ, найденные при проверке

Список ошибок и недочётов, которые были в документе, написанном с помощью ИИ, и как они исправлены. Источник: внешний разбор от 17.11.2026 и повторная проверка документа.

| № | Где | Что было не так | Как исправлено |
|---|---|---|---|
| 1 | Первая версия, база | Деньги хранились в `Float` (ошибки округления) | `Decimal(12,2)` |
| 2 | Первая версия, API | Статус проверялся только по номеру заявки (номера 1, 2, 3 легко перебрать) | Номер + телефон, одинаковый ответ 404, ограничение частоты запросов |
| 3 | Разд. 1 ↔ таблица статусов | Отмена заявки названа правом администратора, а в таблице переходов её мог выполнять и сотрудник | В обоих местах написано одинаково: сотрудник отменяет до производства, администратор на любом этапе |
| 4 | Разд. 2 ↔ API | Написано «ошибку исправляют отменой», но у гостя не было ни кнопки, ни адреса для отмены | Добавлен `POST /api/public/orders/cancel` (номер + телефон, только «Новая» и «На рассмотрении») |
| 5 | Цена в форме | Не было сказано, кто считает цену до отправки, и формула могла жить в двух местах | Описано: браузер показывает подсказку, сервер считает окончательную цену сам (BR-6) |
| 6 | API ↔ безопасность | Админские `/price` и `/assignee` лежали среди публичных адресов в `/api/orders` | Перенесены в `/api/admin/orders/...`, гостевые адреса вынесены в `/api/public/...` |
| 7 | Вход и роли | Роль бралась только из токена: понижённый администратор оставался им до конца срока токена | Роль берётся из базы при каждом запросе |
| 8 | Структура сервера | Правила статусов названы «в одном месте», а указаны два (`services` и `utils`) | Один файл `services/orderStatus.js` |
| 9 | Раздел 5.5 | Поле `estimated_price` (сумма позиций) было повтором данных, но не отмечено как осознанное | Пояснено: снимок суммы на момент заказа |
| 10 | Текст документа | Обращение к читателю («вы решили», «если вам не подходит») вместо описания собственных решений | Раздел переписан как «Мои решения» |
| 11 | BR-3 | Не было правила про телефон с ведущей 8 (проверка «номер + телефон» не нашла бы заявку) | Правило нормализации 8 → 7 |
| 12 | BR-2 | БИН/ИИН «10–12 цифр» (правило российского ИНН) для проекта по Казахстану | Ровно 12 цифр |
| 13 | Процессы | Нельзя исправить ошибку в телефоне клиента | `PATCH /api/orders/:id/customer` с записью в историю |
| 14 | Процессы | Негде сменить временный пароль | `POST /api/auth/change-password`, сброс паролей администратором, флаг `must_change_password` |
| 15 | История | Записывалась только смена статуса: изменения цены и ответственного не были видны | Таблица `order_history` с типом события и значениями «было / стало» |
| 16 | Файлы | При ошибке сохранения заявки файлы оставались на диске | Временная папка, перенос после успешного сохранения |
| 17 | Данные | Не было согласия на обработку персональных данных | Галочка в форме и поле `consent_at` |
| 18 | Мелочи | Опечатка в BR-4, нет индекса на `assignee_id`, не указан часовой пояс, ограничение запросов только по IP | Исправлено |
