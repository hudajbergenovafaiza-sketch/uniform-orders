# CLAUDE.md — правила проекта uniform-orders

Веб-система управления заявками на пошив униформы. Перед любой работой читай `docs/` (там описаны роли, правила, база, API и страницы).

## Стек (не менять)

React (Vite) + Node.js + Express + PostgreSQL + Prisma.

## Структура

- `client/` — React-приложение.
- `server/` — Express, слои `routes → controllers → services → database`.
- `docs/` — архитектура и документация. При изменении логики сначала обновляем документацию.

## Главные правила

1. **Слои.** Бизнес-правила живут только в `services`. Контроллер не обращается к Prisma напрямую.
2. **Цену считает сервер.** Цену из запроса игнорируем. Цена позиции фиксируется в `order_items.unit_price` в момент заказа.
3. **Деньги — `Decimal`, не `Float`.**
4. **Статус, цена, назначение, отмена и правка контактов** меняются только через сервис. Правила статусов лежат в одном файле `services/orderStatus.js`. Каждое изменение пишется в `order_history`.
5. **Создание заявки — одна транзакция** (`prisma.$transaction`): заявка, позиции, файлы, история.
6. **Телефон нормализуем:** только цифры, ведущая 8 заменяется на 7 (11 цифр).
7. **Гость видит и отменяет заявку только по паре «номер + телефон».** При ошибке всегда одинаковый ответ 404.
8. **Роль пользователя берём из базы**, а не только из токена.
9. **Все проверки данных — на сервере** (`validators/`). Браузер только подсказывает.
10. **Секреты только в `.env`.** В Git лежит `.env.example` без значений. Папка `uploads/` не в Git и не открыта публично.
11. **Время считаем по `Asia/Almaty`.**
12. **Пароли — bcrypt, не короче 8 символов.** Временный пароль нужно сменить при первом входе.

## Как отвечать

Простым языком. Термины объяснять в скобках. Код писать только по запросу.
